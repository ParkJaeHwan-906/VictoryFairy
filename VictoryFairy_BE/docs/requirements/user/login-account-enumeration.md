# 로그인 응답시간 계정 열거 차단 요구사항
> 상태: **승인됨 (2026-09-18)** · 모듈: user · 최종 수정: 2026-09-18
> 2026-09-18 사용자 결정 반영 — 미해결 질문 3건 해소, USER-LAE-9 철회, USER-LAE-13 신설.

## 배경 / 목적
`AuthService.login`은 응답 **내용**으로는 이미 계정 존재를 감춘다(미가입·탈퇴·비밀번호 오답이 전부 같은 401 `INVALID_CREDENTIALS`, `docs/api/auth.md`). 그런데 감추는 주체가 코드가 아니라 **쿼리 조건**(`findByUser_EmailAndExitAtIsNull`)이라, 계정을 못 찾으면 `passwordEncoder.matches()`를 **아예 타지 않고** 즉시 예외로 빠진다. BCrypt 검증은 cost 10에서 수십~수백 ms라, 응답시간만 재면 "그 이메일이 가입돼 있는가"가 그대로 드러난다 — 내용으로 막은 열거를 **시간이라는 부채널**이 되돌려 놓는 상태다.

이 문서는 **두 갈래의 응답시간을 맞추는 계약**만 확정한다. 응답 내용(상태코드·에러코드·본문)은 한 글자도 바뀌지 않는다.

## 범위
- 포함:
  - 계정 조회 실패 시에도 **비밀번호 검증을 1회 수행**해 응답시간을 가입 계정 갈래와 맞추는 계약
  - 그 더미 검증이 **인증 성공으로 절대 이어지지 않는다**는 안전 계약
  - 탈퇴 계정·소셜 전용 계정처럼 "조회는 되지만 BCrypt를 안 타는" 갈래의 처리
  - 동등성의 **관측 가능한 판정 기준**(응답 동일성 + 응답시간 차이 상한)
- 제외:
  - **에러코드·HTTP 상태·응답 본문 변경** — 전부 현행 유지(401 `INVALID_CREDENTIALS`). 이 문서는 시간 축만 다룬다.
  - **로그인 시도 횟수 제한·계정 잠금·CAPTCHA** — 무차별 대입 방어는 별개 주제이고 이번 범위가 아니다.
  - **`POST /api/auth/refresh`·`/logout`의 타이밍** — 두 경로는 입력이 토큰이라 이메일 단위 열거기가 성립하지 않는다.
  - **`PATCH /api/users/me/password`의 현재 비밀번호 대조 타이밍** — access 토큰으로 이미 본인이 확정된 경로라 열거 대상이 아니다.
  - **소셜 로그인 경로(`oauth.*`) 전반** — 2026-09-18 사용자 결정: **소셜 로그인은 현재 연결돼 있지 않으므로 이번 작업은 자체 로그인만 다룬다.** 소셜 전용 계정의 잠금 비밀번호가 만드는 타이밍 갈래도 이번 범위가 아니다(아래 "남는 한계" 참고).

## 요구사항 (EARS)

| ID | 유형 | 요구사항 | 인수 기준 |
|---|---|---|---|
| USER-LAE-1 | 유비쿼터스 | THE 시스템 SHALL 형식 검증을 통과한 모든 로그인 요청에 대해 비밀번호 검증을 정확히 1회 수행한다 | `POST /api/auth/login`이 미가입·탈퇴·가입(오답)·가입(정답) 어느 갈래로 가든 `PasswordEncoder.matches()` 호출 횟수가 1이다(유닛 테스트에서 목 호출 횟수로 검증) |
| USER-LAE-2 | 예외 | IF 요청 이메일에 해당하는 활성 계정이 없으면, THEN THE 시스템 SHALL 고정 더미 해시를 대상으로 요청 비밀번호를 검증한 뒤 401과 `INVALID_CREDENTIALS`를 반환한다 | 미가입 이메일로 `POST /api/auth/login` → 401, `{"success":false,"data":null,"message":"이메일 또는 비밀번호가 올바르지 않습니다."}`. 검증 호출이 더미 해시를 인자로 1회 발생 |
| USER-LAE-3 | 유비쿼터스 | THE 시스템 SHALL 더미 해시를 실제 계정 비밀번호와 동일한 알고리즘·동일한 cost(BCrypt, `SecurityConfig`의 `BCryptPasswordEncoder` 기본값 10)로 생성된 값으로 둔다 | 더미 해시가 `^\$2[aby]\$10\$` 를 만족한다. `BCryptPasswordEncoder`가 "does not look like BCrypt" 경고를 남기지 않는다 |
| USER-LAE-4 | 유비쿼터스 | THE 시스템 SHALL 더미 해시 검증 결과와 무관하게 토큰을 발급하지 않는다 | 더미 해시 검증이 `true`를 돌려주도록 강제한 테스트에서도 응답은 401이고 `UserRefreshToken` 행이 생기지 않는다(검증 결과가 분기 조건으로 쓰이지 않음) |
| USER-LAE-5 | 유비쿼터스 | THE 시스템 SHALL 더미 해시의 원문 비밀번호를 어떤 계정에도 저장하지 않는다 | 더미 해시 값이 `users_account.password` 컬럼의 어떤 행과도 일치하지 않는다. 더미 해시는 상수 1개로만 존재하고 계정 생성 경로(`signup`·소셜 가입)에서 참조되지 않는다 |
| USER-LAE-6 | 예외 | IF 요청 이메일의 계정이 탈퇴 계정(`exit_at IS NOT NULL`)이면, THEN THE 시스템 SHALL 미가입 이메일과 동일하게 더미 해시 검증을 수행하고 401을 반환한다 | 탈퇴 계정 이메일 + 탈퇴 전의 정확한 비밀번호로 로그인 → 401 `INVALID_CREDENTIALS`. 응답시간이 USER-LAE-8 기준으로 미가입 갈래와 구분되지 않는다 |
| USER-LAE-7 | 유비쿼터스 | THE 시스템 SHALL 미가입·탈퇴·비밀번호 오답 세 갈래의 실패 응답을 상태코드·본문·헤더까지 동일하게 반환한다 | 세 갈래 응답의 상태코드(401)·본문 바이트·`Content-Type`이 서로 같다. 갈래를 구분할 수 있는 헤더(예: 전용 `X-` 헤더)가 없다 |
| USER-LAE-8 | 유비쿼터스 | THE 시스템 SHALL 미가입 이메일 요청과 가입 이메일+오답 비밀번호 요청의 응답시간이 유의미하게 갈리지 않게 한다 | **자동 검증은 구조 동등성으로 한다**: 두 갈래 모두 `PasswordEncoder.matches()` 1회 호출(USER-LAE-1)이며 더미 해시의 cost가 실제 해시와 같다(USER-LAE-3). 실제 시간 측정은 아래 "수동 실측 항목"으로 분리한다(CI 머신 편차로 간헐 실패하는 테스트를 만들지 않기 위함 — 2026-09-18 결정) |
| ~~USER-LAE-9~~ | ~~예외~~ | **(2026-09-18 철회 — 소셜 로그인이 이번 범위 밖이라는 사용자 결정. 번호는 재사용하지 않는다. 잔여 위험으로만 남긴다)** ~~IF 요청 이메일의 활성 계정 비밀번호가 BCrypt 형식이 아닌 잠금 예약값이면, THEN THE 시스템 SHALL 그 값 대신 더미 해시로 검증을 수행한다~~ |
| USER-LAE-10 | 예외 | IF 로그인 요청의 `email`·`password`가 Bean Validation을 위반하면, THEN THE 시스템 SHALL 비밀번호 검증을 수행하지 않고 400을 반환한다 | `{"email":"not-an-email","password":""}` → 400, `PasswordEncoder.matches()` 호출 0회. 형식 위반은 이메일 존재 여부와 무관하므로 타이밍 동등화 대상이 아니다 |
| USER-LAE-11 | 이벤트 | WHEN 활성 계정의 비밀번호가 일치하면, THE 시스템 SHALL 종전과 동일하게 access·refresh 토큰 쌍을 반환한다 | 정상 자격증명으로 로그인 → 200 + `{"accessToken","refreshToken"}`(raw, `ApiResponse` 미사용). 기존 유효 refresh 토큰 전량 만료 동작도 불변 |
| USER-LAE-12 | 유비쿼터스 | THE 시스템 SHALL 더미 해시 검증 경로에서 데이터베이스 쓰기를 발생시키지 않는다 | 미가입 이메일로 로그인 100회 후 `users`·`users_account`·`user_refresh_token` 행 수 불변 |
| USER-LAE-13 | 유비쿼터스 | THE 시스템 SHALL 더미 해시를 코드에 고정된 상수 1개로 둔다 | 더미 해시 값이 기동마다·파드마다 동일하다(런타임 생성 아님). 기동 시 BCrypt 인코딩 비용이 추가로 들지 않는다. 안전성은 USER-LAE-4(검증 결과가 분기 조건이 아님)·USER-LAE-5(원문 미저장)가 담보한다 — 2026-09-18 결정 |

## 수동 실측 항목 (자동 테스트로 강제하지 않는다 — 2026-09-18 결정 3)
배포 전 1회, 운영과 같은 사양의 환경에서 확인한다. **CI 파이프라인에 넣지 않는다.**
- 미가입 이메일 100회 / 가입 이메일+오답 비밀번호 100회를 각각 요청해 서버 처리시간 중앙값을 비교한다.
- 기대: 두 중앙값 차이가 BCrypt 1회 소요(cost 10 기준 수십~수백 ms)에 비해 무시할 수준이고, 미가입 갈래 중앙값이 가입 갈래 중앙값과 같은 자릿수다(= 더미 검증이 실제로 BCrypt 1회를 태우고 있다).
- 어긋나면 USER-LAE-1(호출 1회)·USER-LAE-3(cost 일치) 중 하나가 깨진 것이므로 그 둘을 먼저 본다.

## 남는 한계 (이 문서가 닫지 못하는 것)
- **네트워크·GC·커넥션 풀 편차**는 그대로 남는다. 이 문서의 계약은 "부채널을 0으로 만든다"가 아니라 "BCrypt 1회(수십~수백 ms)만큼의 **구조적** 차이를 없앤다"이다.
- **잠금 비밀번호 계정(소셜 전용 `SocialAccountPolicy.LOCKED_PASSWORD`·`(알수없음)` 더미 계정)은 여전히 빠르게 응답한다.** 그 값이 BCrypt 형식이 아니라 `matches()`가 형식 불일치로 즉시 false를 내기 때문이며, 이 패치 후에도 "그 주소는 잠금 계정"이라는 사실은 타이밍으로 드러난다. **소셜 로그인이 실제로 연결되는 시점에 반드시 재검토할 것**(2026-09-18 결정: 지금은 소셜이 연결돼 있지 않아 범위 밖).
- **`POST /api/auth/email/send-code`가 열려 있으면 이 패치의 효과가 상쇄된다.** 개정 전 그 경로는 409로 가입 사실을 그대로 알려 준다(USER-EMV-14) — 같은 날 `docs/requirements/user/email-verification.md` 개정분(USER-EMV-19~31)이 그것을 닫는다. **두 패치는 함께 적용되어야 의미가 있다.**

### 해소 기록
1. 잠금 예약값 계정 동등화 → **B(범위 밖)**. USER-LAE-9 철회, 잔여 위험으로만 기록(소셜 로그인 연결 시 재검토).
2. 응답시간 수치 고정 → **C**. 계약 문구는 "유의미하게 갈리지 않는다"로 두고, 자동 테스트는 `matches()` 1회 호출(결정론적)로만 강제한다. 수치 실측은 "수동 실측 항목"으로 분리.
3. 더미 해시 출처 → **A(코드 상수)**. USER-LAE-13으로 명문화.

## 기존 정책과의 충돌
- **`.claude/modules/user.md`의 "login 탈퇴 판정은 쿼리 조건이 하는 일"** — "탈퇴 계정이 못 찾음으로 흡수돼 bcrypt 검사조차 안 탄다"고 명시돼 있고, 그 서술의 **후반부가 이 문서로 뒤집힌다**(응답 내용은 그대로, bcrypt는 이제 탄다). 쿼리 조건으로 흡수한다는 구조 자체는 유지된다. 반영은 `context-keeper` 소관.
- **`docs/api/auth.md`의 login 절**("비밀번호 검사조차 하지 않고 곧바로 같은 401") — 같은 이유로 사후 갱신 필요(`api-documenter` 소관). 외부 계약(상태·본문)은 불변이라 **파괴적 변경은 아니다**.
- **비밀번호 재사용 금지 원칙과의 정합** — USER-LAE-5가 더미 원문을 어떤 계정에도 두지 않으므로, "아무도 모르는 비밀번호로 로그인 가능한 계정"을 만들지 않는다는 `SocialAccountPolicy`의 경고와 같은 선에 있다. 더미 해시를 코드 상수로 두는 USER-LAE-13도 이 보장 위에서만 안전하다 — **USER-LAE-4/5를 빼면 상수 노출이 곧 로그인 가능한 값의 노출이 된다.**
- **`docs/requirements/user/email-verification.md` 개정분(USER-EMV-19~38)과 짝이다.** 두 패치는 같은 목적(계정 열거 차단)의 앞뒷면이라 **함께 적용되어야 의미가 있다** — 한쪽만 적용하면 다른 쪽 경로로 같은 정보가 그대로 샌다.
